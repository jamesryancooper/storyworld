# Storyworld Commerce Foundry Bridge Checklist

## Intake

- [ ] Exact request and expected side effects are stated.
- [ ] Repository revision, branch, and dirty state are known.
- [ ] Applicable `AGENTS.md` and `.agent/` governance were read.
- [ ] Relevant accepted and staged decisions were classified separately.
- [ ] A task record exists for significant work.
- [ ] External crossings, credentials, spending, publication, or deployment are explicitly gated.

## Scope and authority

- [ ] The skill is applicable and the task is not better routed elsewhere.
- [ ] Required inputs are available:
  - [ ] `CommerceFoundryBrief_or_StoryworldCommerceBundle`
  - [ ] `exact_versions`
  - [ ] `authority_host`
  - [ ] `rights_and_commercial_policy`
- [ ] Durable semantic changes have decision-impact analysis.
- [ ] Provider/editor/runtime private formats remain behind Storyworld-owned boundaries.
- [ ] No skill, plan, fixture, or passing test is treated as permission.

## Implementation or assessment

- [ ] Receive immutable brief/product/claim/offer inputs under Commerce Foundry authority
- [ ] Pin exact versions into Storyworld production context without copying authority
- [ ] Create Storyworld creative assets, rights evidence, evaluations, and bundle receipts
- [ ] Send immutable creative/print package as an unapproved commercial candidate
- [ ] Receive Commerce Foundry commercial findings, approval/rejection, publication, vendor, order, and fulfillment status
- [ ] Store normalized references and receipts without claiming the external state
- [ ] Handle supersession and rework across the peer-system boundary

## Invariants

- [ ] Verified: Approval layers never imply one another
- [ ] Verified: Product truth and claims remain Commerce Foundry-owned
- [ ] Verified: Storyworld keeps standalone portable exports
- [ ] Verified: External receipts are evidence of peer-host state

## Validation

- [ ] Commercial rejection of creatively accepted package
- [ ] Stale product/claim snapshot
- [ ] Print proof failure
- [ ] Authority-host outage
- [ ] Receipt mismatch
- [ ] Vendor credential separation

## Closure

- [ ] Required outputs exist:
  - [ ] `CommerceFoundryBrief`
  - [ ] `StoryworldCommerceBundle`
  - [ ] `CommerceFoundryReceipt`
  - [ ] `commercial_findings`
  - [ ] `status_projection`
  - [ ] `rework_proposal`
- [ ] Actual commands/results and skipped checks are recorded.
- [ ] Findings name evidence, impact, remedy, and disposition owner.
- [ ] No generated file was hand-edited.
- [ ] Dirty state and unrelated changes are disclosed.
- [ ] External effects and costs are listed, including “none.”
- [ ] The result does not overclaim acceptance, readiness, or external success.

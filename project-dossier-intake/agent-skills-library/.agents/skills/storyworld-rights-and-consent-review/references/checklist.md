# Storyworld Rights And Consent Review Checklist

## Intake

- [ ] Exact request and expected side effects are stated.
- [ ] Repository revision, branch, and dirty state are known.
- [ ] Applicable `AGENTS.md` and `.agent/` governance were read.
- [ ] Relevant accepted and staged decisions were classified separately.
- [ ] A task record exists for significant work.
- [ ] External crossings, credentials, spending, publication, or deployment are explicitly gated.

## Scope and authority

- [ ] The skill is applicable and the task is not better routed elsewhere.
- [ ] Required inputs are available:
  - [ ] `subject_or_asset_identity`
  - [ ] `rights_evidence`
  - [ ] `consent_state`
  - [ ] `intended_use`
  - [ ] `provider_or_destination`
- [ ] Durable semantic changes have decision-impact analysis.
- [ ] Provider/editor/runtime private formats remain behind Storyworld-owned boundaries.
- [ ] No skill, plan, fixture, or passing test is treated as permission.

## Implementation or assessment

- [ ] Identify parties, assets, likenesses, voices, brands, source works, and jurisdictions implicated
- [ ] Record permission basis, purpose, medium, territory, channel, duration, modification, cloning, training, provider, and publication scope
- [ ] Resolve expiry, revocation, attribution, disclosure, and conflict rules
- [ ] Apply the most restrictive access, egress, retention, rights, consent, and contractual rule
- [ ] Create deterministic blockers for absent, expired, revoked, or prohibited uses
- [ ] Route ambiguous legal or ethical questions to qualified human review
- [ ] Invalidate affected generation, evaluation, approval, package, and publication state when rights change

## Invariants

- [ ] Verified: Possessing media is not permission
- [ ] Verified: Consent cannot override law, contract, or no-egress rules
- [ ] Verified: Legal and ethical review are distinct
- [ ] Verified: Storyworld never claims automated legal certainty

## Validation

- [ ] Expired consent, revoked likeness, prohibited cloning, territory/channel mismatch, provider retention conflict, minor/highly-restricted fixture

## Closure

- [ ] Required outputs exist:
  - [ ] `rights_record`
  - [ ] `consent_record`
  - [ ] `provider_egress_gate`
  - [ ] `findings`
  - [ ] `approval_invalidation`
  - [ ] `disclosure_requirements`
  - [ ] `review_request`
- [ ] Actual commands/results and skipped checks are recorded.
- [ ] Findings name evidence, impact, remedy, and disposition owner.
- [ ] No generated file was hand-edited.
- [ ] Dirty state and unrelated changes are disclosed.
- [ ] External effects and costs are listed, including “none.”
- [ ] The result does not overclaim acceptance, readiness, or external success.

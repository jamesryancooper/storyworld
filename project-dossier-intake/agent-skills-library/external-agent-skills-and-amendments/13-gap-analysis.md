# External Skill Gap Analysis

## Areas with mature reusable external guidance

- React composition and performance.
- General UI implementation and accessibility baselines.
- API/interface design and schema evolution.
- PostgreSQL engineering.
- Source-driven and incremental development.
- Systematic debugging and verification.
- Property and mutation testing.
- Skill authoring, progressive disclosure, trigger evaluation, and skill scanning.
- General secure coding, supply chain, CI-agent prompt injection, and executable hardening.
- Browser automation and evidence capture.

## Areas with no adequate reusable external Storyworld skill

The search did not find a credible public skill package that safely covers:

- Storyworld intent interpretation and typed creative operations.
- Partial proposal acceptance and exact creative revisions.
- Canon, continuity, truth, belief, secrecy, spoilers, adaptations, and human authority.
- OpenRouter policy-equivalent routing and no-fallback profiles.
- fal.ai queue, webhook, URL expiry, storage headers, immediate custody, and late completion.
- Storyworld’s hosted-endpoint-only self-hosted ComfyUI posture.
- External-editor checkout/return with nonauthoritative workfiles.
- Provider-neutral creative specifications versus execution plans.
- Real-person consent, provider egress, and rights-aware generative workflows.
- Commerce Foundry peer authority.
- Browser/Godot shared runtime contract and working-canon protection.

These areas should remain project-authored and use current official product documentation as mutable technical evidence.

## Why absence matters

The absence of a suitable skill is not a reason to broaden generic provider or media skills. Storyworld’s differentiated value lies precisely in the semantics that external tool vendors do not own. The external ecosystem should supply engineering technique; Storyworld must supply creative and governance meaning.

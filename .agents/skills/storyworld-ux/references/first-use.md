# Conditional protected first-use pass

Use this protocol only for a new-creator, first-use, cold-start, or unguided
Studio audit when a safe unprimed local rendered evaluation is available. This
is synthetic evaluation, never participant evidence.

## Decide whether the protected pass is available

Run the pass only when all conditions hold:

- The request tests initial orientation or discoverability.
- Studio can be rendered through a verified project-owned loopback service
  using clearly synthetic data.
- A fresh ephemeral browser context is available without an existing profile,
  session, cookies, storage, login, credential, provider, or production data.
- The evaluator has not already inspected product context, Studio routes,
  implementation sources, behavior tests, glossaries, help, or the intended
  journey for this audit.
- Unexpected external requests can be blocked or aborted.

If any condition fails, do not imitate or claim an unprimed pass. Record the
specific limitation—unsafe stack, unavailable browser, prior knowledge, or
already-inspected intended path—then continue the normal workflow from
`product-context.md`. Existing authority, evidence, and browser boundaries
remain in force.

## Limit pre-pass context

Before the protected pass, read only:

- Current operator and platform instructions.
- Applicable repository authority and safety material.
- The available browser-control skill/tool instructions.
- The minimum local startup, port, and synthetic-entry information needed to
  verify and open Studio safely.
- This reference.

Do not use product context, implementation code, component or behavior tests,
route maps, glossaries, help content, canonical intended journeys, API/database
inspection, or prior audit conclusions to discover the path. Do not mine
required authority records for navigation help. Record any unavoidable product
knowledge as evaluator contamination.

## Record the raw walkthrough

Enter Studio through a fresh synthetic local browser context. Attempt the
visible journey without help first. Keep a chronological record:

```text
Beginning state:
- entry URL and visible first viewport
- apparent selected world/property, production, and status
- evaluator contamination or prior knowledge

Initial interpretation:
- what Studio appears to help a creator do
- what appears official versus draft, proposed, candidate, or released
- what appears controlled by a person versus assisted by AI
- apparent primary action and why

Meaningful action:
- visible control and current state
- expected outcome before acting
- expected authority/state change and confidence
- observed outcome after acting
- surprise, mismatch, confusion, hesitation, wrong turn, or backtrack
- recovery attempted and whether work/context appeared preserved

Help check:
- help used only after the unaided attempt
- whether help was discoverable, timely, and sufficient

Ending state:
- final route and visible world/property or production
- apparent canon, proposal, continuity, review, release, and publication state
- unresolved questions, unsafe ambiguity, or next step
```

Record a new action block before each meaningful navigation, proposal/review
decision, continuity disposition, release action, or other state-changing
control. Do not rewrite an expectation after seeing the result. Completion
through guessing, hunting, or prior knowledge remains friction.

## Perform expert verification afterward

After saving the raw record—or the reason the pass was unavailable—load
`product-context.md` and the task-specific critique, accessibility, and visual
QA references. Inspect current routes, implementation, API state, tests,
accepted scope, and canonical intent.

Compare expert evidence with the raw walkthrough:

- Confirm or correct the evaluator's interpretation in a separate section.
- Explain expectation-versus-result mismatches and their likely consequence.
- Preserve contradictions, wrong turns, help use, and uncertainty.
- Never revise the raw notes to match intended behavior.
- Keep every first-use observation labeled synthetic and distinguish it from
  observed repository/runtime facts, heuristic inference, and any real
  participant evidence.
